There are two primary reasons for following naming conventions in your TinaCMS project:

* **Improved hot reloads**: Rebuilding your schema is an expensive process and keeping your schemas in separate files prevents rebuilds making code changes
* **Improved code scanning**: It's easy to find the schema configuration for a React component when it has the same file name as the component

## Naming Conventions

| naming convention | Purpose                                                                                             |
| ----------------- | --------------------------------------------------------------------------------------------------- |
| `.schema.tsx`     | Used for collections and code shared between collections                                            |
| `.template.tsx`   | Used for template definitions used for [block-based rendering](https://tina.io/docs/editing/blocks) |

### React components

The typical convention is to add the schema for a given React component to an accompanying file of the same name with the suffix `schema.tsx`. This ensures your index is only rebuilt when changes are made to your data model and not to the component.

<fileStructure
  fileStructure={[
    { id: "nc1-src", name: "src", type: "folder", parentId: null },
    { id: "nc1-app", name: "app", type: "folder", parentId: "nc1-src" },
    { id: "nc1-components", name: "components", type: "folder", parentId: "nc1-app" },
    { id: "nc1-schema", name: "events-list.schema.tsx", type: "file", parentId: "nc1-components" },
    { id: "nc1-component", name: "events-list.tsx", type: "file", parentId: "nc1-components" }
  ]}
/>

### Shared Fields

Code shared between multiple collections, including field definitions and lists of field definitions are also typically stored in files ending in `.schema.tsx`. In the Example below assume we are sharing the `title` field between the `hero-image` and image-text-block. Component.

<fileStructure
  fileStructure={[
    { id: "nc2-src", name: "src", type: "folder", parentId: null },
    { id: "nc2-tina", name: "tina", type: "folder", parentId: "nc2-src" },
    { id: "nc2-collections", name: "collections", type: "folder", parentId: "nc2-tina" },
    { id: "nc2-shared-fields", name: "shared-fields", type: "folder", parentId: "nc2-collections" },
    { id: "nc2-title-schema", name: "title.schema.tsx", type: "file", parentId: "nc2-shared-fields" },
    { id: "nc2-app", name: "app", type: "folder", parentId: "nc2-src" },
    { id: "nc2-components", name: "components", type: "folder", parentId: "nc2-app" },
    { id: "nc2-blocks", name: "blocks", type: "folder", parentId: "nc2-components" },
    { id: "nc2-hero-schema", name: "hero-image.schema.tsx", type: "file", parentId: "nc2-blocks" },
    { id: "nc2-hero", name: "hero-image.tsx", type: "file", parentId: "nc2-blocks" },
    { id: "nc2-itb-schema", name: "image-text-block.schema.tsx", type: "file", parentId: "nc2-blocks" },
    { id: "nc2-itb", name: "image-text-block.tsx", type: "file", parentId: "nc2-blocks" }
  ]}
/>

### Naming conventions for blocks

If you're re-using the template for a block component between multiple collections it's good practice to separate that template into a file ending in `.template.tsx`.

> `templates` are passed into existing collections using a [block-based editing](https://tina.io/docs/editing/blocks)

In the example below, assume we are using the `image-carousel` block template in the our block renderer. The `image-carousel` template can be shared between the `home` and `about` collections.

<fileStructure
  fileStructure={[
    { id: "nc3-src", name: "src", type: "folder", parentId: null },
    { id: "nc3-tina", name: "tina", type: "folder", parentId: "nc3-src" },
    { id: "nc3-collections", name: "collections", type: "folder", parentId: "nc3-tina" },
    { id: "nc3-home", name: "home.tsx", type: "file", parentId: "nc3-collections" },
    { id: "nc3-about", name: "about.tsx", type: "file", parentId: "nc3-collections" },
    { id: "nc3-app", name: "app", type: "folder", parentId: "nc3-src" },
    { id: "nc3-components", name: "components", type: "folder", parentId: "nc3-app" },
    { id: "nc3-blocks", name: "blocks", type: "folder", parentId: "nc3-components" },
    { id: "nc3-carousel", name: "image-carousel.tsx", type: "file", parentId: "nc3-blocks" },
    { id: "nc3-carousel-template", name: "image-carousel.template.tsx", type: "file", parentId: "nc3-blocks" },
    { id: "nc3-renderer", name: "blocks-renderer.tsx", type: "file", parentId: "nc3-blocks" }
  ]}
/>
